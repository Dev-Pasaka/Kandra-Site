# Getting started

Five minutes: install, one entity, one query, against a real (local) ScyllaDB instance. This page
intentionally skips the reasoning behind every decision — for that, go build the full app in
[`/tutorial`](/tutorial), which explains every line as it's written. If you haven't read
[`/foundations`](/foundations) yet, do that first; nothing below will feel arbitrary once you have.

<Callout kind="note">
You need JDK 21 or newer and Docker for a local ScyllaDB instance. Start from an empty Gradle
Kotlin project; the build file below is complete. Every dependency is explained in
[`/tutorial/02-project-setup`](/tutorial/02-project-setup).
</Callout>

## 1. Run a local ScyllaDB

```yaml title="docker-compose.yml"
services:
  scylla:
    image: scylladb/scylla:latest
    ports:
      - "9042:9042"
    command: --smp 1 --memory 750M --overprovisioned 1 --api-address 0.0.0.0
```

```bash
docker compose up -d
```

## 2. Add the dependencies

```kotlin title="build.gradle.kts"
plugins {
    kotlin("jvm") version "2.1.21"
    kotlin("plugin.serialization") version "2.1.21"
    id("com.google.devtools.ksp") version "2.1.21-2.0.1"
    application
}

application {
    mainClass.set("com.example.ApplicationKt")
}

repositories {
    mavenCentral()
}

dependencies {
    val kandraBom = platform("ke.co.coinx.kandra:kandra-bom:__KANDRA_VERSION__")
    implementation(kandraBom)
    ksp(kandraBom)
    implementation("ke.co.coinx.kandra:kandra-core")
    implementation("ke.co.coinx.kandra:kandra-runtime")
    implementation("ke.co.coinx.kandra:kandra-ktor")
    ksp("ke.co.coinx.kandra:kandra-codegen")

    implementation("io.ktor:ktor-server-core:2.3.13")
    implementation("io.ktor:ktor-server-netty:2.3.13")
    implementation("io.ktor:ktor-server-content-negotiation:2.3.13")
    implementation("io.ktor:ktor-serialization-kotlinx-json:2.3.13")
    implementation("org.slf4j:slf4j-simple:2.0.9")
}
```

- **The BOM** pins every Kandra module to one version. It has to be added to `ksp` as well as
  `implementation`: Gradle applies a platform per configuration, so without `ksp(kandraBom)` the
  versionless `kandra-codegen` line can't be resolved.
- **`kandra-core` and `kandra-runtime` are listed explicitly.** Your code imports the annotations
  from `kandra-core` and the repositories from `kandra-runtime`, and in {`v${KANDRA_VERSION}`}
  `kandra-ktor` only brings them in at runtime, not at compile time
  ([kandra#152](https://github.com/Dev-Pasaka/kandra/issues/152)).
- **`kandra-codegen`** runs at build time through KSP and generates a type-safe `UserTable` for the
  query DSL.
- **Ktor 2.3.x.** Kandra is built and tested against Ktor 2.3. Ktor 3 hasn't been tested with it yet.

[`/tutorial/02-project-setup`](/tutorial/02-project-setup) explains each dependency in depth,
including the dependency-injection modules (`kandra-koin`, `kandra-kodein`).

## 3. Define an entity

```kotlin title="User.kt"
package com.example

import io.kandra.core.annotations.*
import java.time.Instant
import java.util.UUID

@ScyllaTable("users")
data class User(
    @PartitionKey val userId: UUID,
    @LookupIndex(tableSuffix = "by_email", consistency = LookupConsistency.BATCH)
    val email: String,
    val displayName: String,
    @CreatedAt val createdAt: Instant = Instant.EPOCH,
)
```

`@PartitionKey` decides which node(s) this row lives on — see
[`/foundations`](/foundations#what-a-partition-key-actually-is-physically) if "why this column"
isn't obvious yet. `@LookupIndex` generates and maintains a second table, `users_by_email`, so
"find by email" doesn't need a full scan.

## 4. Install the plugin

```kotlin title="Application.kt"
package com.example

import io.kandra.core.KandraAuth
import io.kandra.ktor.*
import io.ktor.serialization.kotlinx.json.*
import io.ktor.server.application.*
import io.ktor.server.engine.*
import io.ktor.server.netty.*
import io.ktor.server.plugins.contentnegotiation.*
import io.ktor.server.routing.*

fun main() {
    embeddedServer(Netty, port = 8080, module = Application::module).start(wait = true)
}

fun Application.module() {
    install(ContentNegotiation) { json() }
    install(Kandra) {
        contactPoints = "localhost:9042"
        keyspace = "quickstart"
        localDatacenter = "datacenter1"
        autoCreateKeyspace = true
        schemaMode = SchemaMode.AUTO_CREATE
        register(User::class)
        auth { provider = KandraAuth.static("cassandra", "cassandra") } // local dev only, see below
    }
    routing { userRoutes() }
}
```

`schemaMode = SchemaMode.AUTO_CREATE` runs `CREATE TABLE IF NOT EXISTS` for every registered
entity at startup — right for a quickstart, not what you'd run in a production deploy pipeline (see
[`/philosophy/schema-safety`](/philosophy/schema-safety)).

<Callout kind="gotcha" title="The auth block isn't optional, even for an unauthenticated local cluster">
`AuthConfig.provider` defaults to `KandraAuth.fromEnv()`, and `install(Kandra)` calls it
unconditionally while building the driver session — there's no "skip auth for local dev" default.
Without the override above, this app throws `KandraAuthException` at startup unless
`SCYLLA_USERNAME`/`SCYLLA_PASSWORD` are set in the environment, even though the docker-compose
ScyllaDB above has no authentication enabled. `KandraAuth.static(...)` is fine for local dev;
`KandraAuth.fromEnv()` (the default) is the right choice once there's a real cluster with real
credentials. The tutorial uses it with exported environment variables; see
[`/tutorial/04-plugin-install`](/tutorial/04-plugin-install).
</Callout>

## 5. Save and query

```kotlin title="Routes.kt"
package com.example

import io.kandra.ktor.kandra
import io.ktor.http.*
import io.ktor.server.application.*
import io.ktor.server.request.*
import io.ktor.server.response.*
import io.ktor.server.routing.*
import kotlinx.serialization.Serializable
import java.util.UUID

@Serializable
data class CreateUserRequest(val email: String, val displayName: String)

@Serializable
data class UserResponse(val userId: String, val email: String, val displayName: String)

fun User.toResponse() = UserResponse(userId.toString(), email, displayName)

fun Route.userRoutes() {
    val userRepo = application.kandra.suspendRepository<User>()

    post("/users") {
        val req = call.receive<CreateUserRequest>()
        val user = User(userId = UUID.randomUUID(), email = req.email, displayName = req.displayName)
        userRepo.save(user)
        call.respond(HttpStatusCode.Created, user.toResponse())
    }

    get("/users/by-email/{email}") {
        val email = call.parameters["email"]!!
        val user = userRepo.find { UserTable.email eq email }
        if (user == null) call.respond(HttpStatusCode.NotFound) else call.respond(user.toResponse())
    }
}
```

Run it and try it:

```bash
./gradlew run
curl -X POST localhost:8080/users -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","displayName":"Ada"}'
curl localhost:8080/users/by-email/ada@example.com
```

The routes use small request and response classes instead of serializing `User` directly, because
`UUID` and `Instant` need custom serializers that would distract from the point of this page.
[Tutorial page 03](/tutorial/03-entities) shows how to serialize entities directly.
`application.kandra.suspendRepository<User>()` is the plain way to get a typed repository; the
tutorial wires repositories through Koin instead.

`UserTable` is generated by `kandra-codegen` from the `User` entity — a compile-time-checked
reference to the `email` column, not a magic string. `userRepo.find { UserTable.email eq email }`
resolves through the `users_by_email` lookup table Kandra generated in step 3, not a full scan of
`users`.

That's the whole loop: an annotated entity, a plugin install, a type-safe query. Nothing here
explains *why* each piece is shaped this way — that's what the rest of the site is for.
